# e2e-verifier-accuracy-bench

A stdlib-only, offline, deterministic benchmark that measures whether a
*verifier* actually catches bugs: defect detection, false passes, false fails,
and whether each verdict is traceable to a specific element/check.

## HONESTY NOTE
- **All data is synthetic.** The 12 apps and their defects are invented; results are measured
  by executing the synthetic benchmark. Nothing here measures any real product.
- **No real e2e (e2e.com) framework code is touched.** The harness never calls
  or imports e2e's framework, makes no network calls and no LLM calls.
- The two reference verifiers (`careful`, `sloppy`) were written against this
  dataset. Their scores validate the harness; they say nothing about e2e or any
  real verifier. Plug in your own verifier function to measure something real.
- `sample_report/` was generated by running the benchmark with Python 3.13.13.
  Verification: all 32 tests passed. Run `python demo.py --out out` to reproduce
  output, and `python -m unittest discover -s tests -t .` for the tests.

## What it measures
| Metric | Meaning |
|---|---|
| Defect detection rate (recall) | planted defects where a defect-linked check was flagged `fail` / all defects |
| False-pass rate | missed defects / all defects |
| False-fail rate | clean apps given a `fail` verdict / clean apps |
| Per-defect-class breakdown | detection per class (8 classes, one app each) |
| Traceability rate | verdicts citing a known element, their own check id, and non-empty evidence |
| Check-level confusion | TP/FP/FN/TN over checks the verifier ran, plus `not_run` and coverage |

Dataset: 8 defective apps (broken submit handler, wrong cart total, missing
auth redirect, off-by-one pagination, stale data after save, broken mobile nav,
duplicate charge on double-click, timezone-shifted date) and 4 clean apps
(traps: console *warning* only, link-style CTA, correct rounding, etc.).
Ground truth lists the expected pass/fail of every check (59 checks total).

Verifiers: `careful` = surface + static spec checks + simulated click/flow
traces + recomputed derived values. `sloppy` = loads, no console error,
main `button` present.

Judge: layer 1 compares verdict vs ground truth per check; layer 2 checks
traceability.

## Run
```
python demo.py --out out          # prints report, writes out/report.md + out/report.json
python -m unittest discover -s tests -t .
```
Python 3.8+ (stdlib only).

## Add your own verifier
A verifier is `f(app) -> {"app_id", "verifier", "verdict": "pass"|"fail",
"checks": [{"check_id", "result", "cites": {"element","check"}, "evidence"}]}`.
Pass `verifiers={"mine": f}` to `e2ebench.benchmark.run_benchmark`.
